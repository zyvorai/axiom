1. Open the console

  1. Browse to https://<host>:30590/ (or your ingress). Accept the certificate warning once if needed.
  2. Probe health: curl -k https://<host>:30590/api/v1/health.
  3. If NodePort 30590 is taken, redeploy with AXIOM_NODE_PORT=30591 (or another free port).

Lab deploy (remote)

./scripts/deploy-remote.sh <host> <user>
./scripts/deploy-remote.sh <host> <user> --quick          # skip image rebuild
./scripts/deploy-remote.sh <host> <user> --with-atlas     # optional Atlas on same host

Local demo (no cluster)

Follow product QUICKSTART for AXIOM_MODE=demo on port 5090.

2. Sign in

Account Credentials When
Lab demo demo / demo SSO not configured
Operator AXIOM_USERNAME / AXIOM_PASSWORD Secret zyvor-axiom-auth
Local user Settings → Users admin or viewer
SSO OIDC/SAML Settings → Integrations

Use Lab mode — fill demo on the login screen's username step when SSO is off — it fills both fields and jumps straight to the password step.

3. Orient yourself (UX)

  1. Overview — product home (capacity, inventory, utilization) and links into day-2 pages.
  2. Getting Started — live integration checklist.
  3. Sidebar + command palette (⌘K) — Workloads, Pods, Networking, Atlas, Ops, Settings.
  4. Cluster switcher — real multi-cluster activate; demo mode ships three clusters.
  5. Viewer role can read everything but mutating APIs return 403.

4. First useful work

  1. Workloads → Run workload (Form / Intent / YAML).
  2. Open Pods / Pod detail — logs and terminal.
  3. Settings → Integrations — wire Atlas or PacketWolf if needed.

Operate tips

  1. Start on Overview, then Getting Started for integration gaps.
  2. Prefer semantic workload actions (Start/Stop/Restart/Scale/Seal) over raw kubectl for day-2.
  3. Pod detail terminal needs a valid session (WebSocket may use ?access_token= for Basic auth).
  4. Deterministic navigation calls the router — do not send “open Workloads” through an AI helper.
  5. Never paste lab IPs into runbooks — use <host>.

Each recipe assumes you can reach https://<host>:30590/ and have signed in.

Verify a fresh deploy

  1. Deploy: ./scripts/deploy-remote.sh <host> <user> (Getting Started).
  2. curl -k https://<host>:30590/api/v1/health.
  3. Sign in (demo / demo when SSO is off).
  4. Overview → metrics load.
  5. Getting Started checklist.
  6. Nodes → Ready nodes.
  7. Settings → integrations.

If NodePort conflicts: AXIOM_NODE_PORT=30592 ./scripts/deploy-remote.sh <host> <user> --quick.

Connect Atlas

./scripts/deploy-remote.sh <host> <user> --with-atlas

Or Settings → Integrations → Atlas → Save → Test → Atlas → Create volume.

Connect PacketWolf

Set AXIOM_PACKETWOLF_URL (and key) → Networking live flow panel → seal a workload to confirm isolation.

Run and scale a workload

  1. Workloads → Run workload (Form / Intent / YAML).
  2. Open workload detail → owned Pods.
  3. Scale / Restart from the row menu.
  4. Pod detail → Logs / Terminal.

Backup a PVC

  1. Backups → Create snapshot.
  2. Restore to a new PVC name when rehearsing DR.
