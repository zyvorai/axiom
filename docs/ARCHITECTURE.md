```text

  |
  +-- Auth middleware (Basic · OIDC · SAML bridge · API key)
  +-- Workload lifecycle API (scale · stop/start · seal/unseal · rollout)
  +-- Pod API (logs · one-shot exec · interactive terminal WebSocket · evict · window proxy)
  +-- Node API (cordon · drain)
  +-- Network + PacketWolf proxy
  +-- KubeVirt VM lifecycle
  +-- Atlas / Haven / integrations hub
  +-- Helm · GitOps · Velero · agent runs
  +-- Embedded UX (frontend/ → internal/ui/dist/, generated by scripts/sync-ui.sh)
  |
Provider interface (internal/platform)
  |
  +-- DemoProvider (stdlib, deterministic local lab)
  |
  +-- KubernetesProvider (-tags kubernetes, client-go)
        |
        +-- Deployments / StatefulSets / DaemonSets / Services
        +-- Pods / Logs / Exec (one-shot + WebSocket PTY) / Eviction
        +-- Nodes / Events / Namespaces

        +-- Helm 3 releases (when CLI available)
        +-- External Secrets · Velero · Flux/Argo (best-effort list)

      k3s / Kubernetes API server
```

## Provider boundary

`internal/platform/provider.go` is the contract between the API and runtime. The UX never knows whether it is connected to the deterministic lab or a real cluster — the same JSON shapes are returned in both modes. The one deliberate exception is the interactive terminal and Pod `GetResource`/YAML support, which are only registered/implemented under the `kubernetes` build tag; the frontend detects this via `GET /api/v1/realtime/capabilities` and falls back to one-shot exec in demo mode rather than pretending a PTY exists where it can't.

This makes local product development possible without faking HTTP endpoints in the frontend.

## Realtime layer

`GET /api/v1/realtime/capabilities` advertises `interactiveExec` (real WebSocket PTY availability, kubernetes-build-only) and `logFollow`. `GET /api/v1/pods/{namespace}/{name}/terminal` (kubernetes build only) upgrades to a WebSocket and pipes a real PTY (`remotecommand.NewSPDYExecutor` with `TTY:true`) — the client sends raw keystrokes plus a `__resize__:WIDTHxHEIGHT` control message, and receives raw terminal output as binary WebSocket frames. The frontend's `PodTerminal.jsx` component (xterm.js) implements this protocol.

Because a plain WebSocket can't carry a custom `Authorization` header, local Basic-auth sessions authenticate the WebSocket (and the pod-window proxy, and a plain-link navigation to any API route) via `?access_token=<base64 user:pass>` — see `internal/auth/basic.go`'s `credentialsFromRequest`. OIDC/SAML sessions ride their cookie and need nothing extra.

## Integrations hub

Settings persist integration config in-memory (demo) or via the cluster config hub (kubernetes, in a `zyvor-axiom-integrations` ConfigMap + Secret in the Axiom namespace). Supported integrations:

- **Atlas** — storage control-plane proxy and volume intent API (`../atlas`, a separate Rust service); wired automatically when deploying with `--with-atlas` (see [DEPLOYMENT.md](DEPLOYMENT.md))
- **Postgres** — platform database connectivity probe
- **OIDC** — issuer/login URL/client ID for the SSO button (Authorization Code + PKCE, no client secret — register Axiom as a **public** client)
- **HTTP probe** — curl-from-pod or external URL test
- **PacketWolf** — `AXIOM_PACKETWOLF_URL` env (a zeus-os component); status + authenticated API proxy, surfaced as a live eBPF/Cilium flow panel on the Networking page

## Haven identity

When Haven Keycloak is installed in the cluster, `/api/v1/haven/*` surfaces identity plane health for the Ops → Identity tab.

## Kubernetes lifecycle semantics

Axiom does not expose a misleading VM-like "power" abstraction for Kubernetes Pods.

- Workload **Stop** scales Deployments/StatefulSets to zero.
- The previous desired replica count is persisted in `axiom.zyvor.dev/last-replicas` and restored by **Start**.
- **Restart** modifies the Pod template annotation `axiom.zyvor.dev/restarted-at`.
- **Seal / Unseal** apply and remove a deny-all NetworkPolicy for immediate isolation; PacketWolf enriches flow visibility when configured.
- Pod **Evict** uses the policy eviction subresource.
- Node **Drain** cordons the node, skips DaemonSets/mirror Pods/system namespace Pods, then requests evictions.
- KubeVirt VMs get real console *information* (the k8s API subresource path + a copyable `virtctl vnc` command), not a fake embedded VNC client — Axiom has no browser-side VNC/websocket bridge for that subresource.

## Build profiles

### Demo

The default build has zero third-party Go dependencies.

```bash
go build ./cmd/zyvor-axiom
```

### Kubernetes

The production provider is selected at compile time.

```bash
go build -modfile=go.production.mod -tags kubernetes ./cmd/zyvor-axiom
```

The provider first tries in-cluster configuration, then `KUBECONFIG`, then `$HOME/.kube/config`.

## UI source layout

| Path | Role |
|------|------|
| `frontend/src/pages/*.jsx` | One file per route/page |
| `frontend/src/components/*` | Shared shell (Sidebar, TopBar, AppShell), the shadcn/ui primitives under `components/ui/`, and `PodTerminal.jsx` (xterm.js terminal) |
| `frontend/src/lib/*` | `api.js` (axios instance, log streaming, `withAccessToken`), `auth.js`, `cluster.js`, `theme.js` |
| `frontend/src/index.css` | "Liquid Glass" design tokens and utility classes |
| `internal/ui/dist/` | **Generated** embedded copy — gitignored, rebuilt by `./scripts/sync-ui.sh`; never edit directly |
